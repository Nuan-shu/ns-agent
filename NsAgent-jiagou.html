1. tools/registry.py — 工具注册表

创建：v0.1.0 Day 8行数：363 个函数被依赖：全项目
在整个框架中的位置：最先写的代码文件。它是契约——所有工具在此报到，Agent Loop 从此读取。整个框架的「可扩展性」来源于注册表：加工具不改 Loop，改 Loop 不影响工具。
1"""工具注册表 — 所有工具在这里报到。加新工具不改 Agent Loop。"""
2
3_registry = {} # {工具名: {"definition": {...}, "handler": 函数}}
4
5# 调用工具时,会自动来这报道.在tools里调用该函数
6def register(name, definition, handler):
7 """注册一个工具。definition 是给 LLM 看的 JSON Schema。"""
8 _registry[name] = {"definition": definition, "handler": handler}
9
10# 让LLM知道有哪些工具(main函数开具就调用了工具,所以可以直接让LLM知悉)
11def get_tool_definitions():
12 """返回所有工具的 definition 列表（给 LLM 的 tools 参数）。"""
13 return [item["definition"] for item in _registry.values()]
14
15# 执行工具
16def execute(name, args):
17 """根据工具名执行对应函数。"""
18 if name not in _registry:
19 return f"错误：未知工具 {name}"
20 return _registry[name]["handler"](**args)

逐行注解

3_registry = {} — 模块级字典，整个框架唯一的数据中枢。下划线前缀表示模块私有。所有工具的注册、查询、执行都通过这个字典。结构：{"read_file": {"definition": {JSON Schema}, "handler": <函数>}, ...}
6-8register(name, definition, handler) — 契约的第一面。工具模块调用此函数「报到」。三个参数缺一不可：name 是字符串键，definition 是 OpenAI function calling 格式的 JSON Schema（给 LLM 看的「工具说明书」），handler 是真正的 Python 函数引用。一行赋值完成注册，O(1) 写入。
11-13get_tool_definitions() — 契约的第二面。Agent Loop 调用它获取工具列表，拼到 LLM 的 tools 参数里。推导式从 _registry 中只取 definition 部分，handler 不上传给 LLM。Loop 不需要知道工具有几个、叫什么——它只拿到一个 JSON 列表。
16-20execute(name, args) — 契约的第三面。LLM 返回 tool_calls 后，Loop 调此函数执行。查表 O(1)，**args 解包字典为关键字参数传给 handler。查不到返回错误字符串而不抛异常——这是设计选择，因为 Agent 可以处理文本错误，但异常会打断 Loop。
← 被调用：time_tool.py, file_tools.py, terminal_tool.py, search_tool.py→ register()
← 被调用：core/agent.py run()→ get_tool_definitions() / execute()

3. tools/file_tools.py — 文件读写

创建：v0.1.0 Day 8行数：702 函数依赖：registry + pathlib
在整个框架中的位置：比 time_tool 复杂——有参数、有副作用、需要错误处理。一个文件注册两个工具（read_file + write_file），证明「一个模块可以有多个工具」。
1"""文件读写工具 — read_file 和 write_file。"""
2from tools.registry import register
3from pathlib import Path
4
5
6def read_file(path, offset=1, limit=200):
7 """读取文件内容。offset 和 limit 控制读取范围。"""
8 p = Path(path).expanduser().resolve()
9 if not p.exists():
10 return f"错误：文件不存在 {path}"
11 try:
12 lines = p.read_text(encoding="utf-8").split("\n")
13 total = len(lines)
14 start = max(0, offset - 1)
15 end = min(total, start + limit)
16 result = []
17 for i in range(start, end):
18 result.append(f"{i+1}|{lines[i]}")
19 header = f"文件 {path}（第 {start+1}-{end} 行 / 共 {total} 行）\n"
20 return header + "\n".join(result)
21 except Exception as e:
22 return f"错误：读取失败 {e}"
23
24
25def write_file(path, content):
26 """写入文件内容（覆盖）。"""
27 p = Path(path).expanduser().resolve()
28 try:
29 p.parent.mkdir(parents=True, exist_ok=True)
30 p.write_text(content, encoding="utf-8")
31 return f"已写入 {path}（{len(content)} 字符）"
32 except Exception as e:
33 return f"错误：写入失败 {e}"

逐行注解（关键行）

8Path(path).expanduser().resolve() — 三步处理：① Path 包装 ② expanduser 把 ~ 展开为 /Users/ns ③ resolve 把相对路径变成绝对路径。这样 Agent 可以写 ~/file.txt，工具自动转成绝对路径。
9-10文件不存在时返回错误字符串，不抛异常。这是 NsAgent 工具的统一模式——函数返回值永远是字符串，Agent Loop 拿到的永远是文本。
12.read_text() → .split("\n") — 一次性读入全文然后按换行分割。对于几十 KB 的源码文件没问题，不适合 GB 级文件（但 Agent 目前没有读大文件的需求）。
14-15start = max(0, offset-1) —— offset 是给 LLM 看的 1-indexed 行号，转成 0-indexed 数组索引。end 用 min 防越界。
29p.parent.mkdir(parents=True, exist_ok=True) — 自动创建父目录。parents=True 相当于 mkdir -p，多级目录一次性创建。exist_ok=True 防止目录已存在时报错。
69-70文件末尾两次 register()。一个模块注册两个工具——证明注册表不限制每个文件的工具数量。

4. tools/terminal_tool.py — 终端执行

创建：v0.1.0 Day 8行数：391 函数依赖：registry + subprocess
在整个框架中的位置：最强大的工具。Agent 可以通过它执行任何 shell 命令——安装包、运行脚本、查看文件。这是 Agent 从「读」到「写+执行」的质变。也是安全风险最大的工具。
8 try:
9 result = subprocess.run(
10 command, shell=True, capture_output=True,
11 text=True, timeout=timeout, cwd="/Users/ns/Projects/ns-agent"
12 )
13 output = result.stdout
14 if result.stderr:
15 output += "\n[stderr]\n" + result.stderr
16 return output or f"命令执行完毕（退出码 {result.returncode}）"
17 except subprocess.TimeoutExpired:
18 return f"错误：命令超时（>{timeout}秒）"

逐行注解

9-12subprocess.run() — 五个关键参数：① shell=True 允许管道/重定向（如 ls | grep py）；② capture_output=True 捕获 stdout 和 stderr 到内存；③ text=True 返回字符串而非 bytes；④ timeout=30 防止命令挂死；⑤ cwd 固定工作目录，让 Agent 的命令在项目目录下执行。
14-15合并 stderr：不是只返回 stdout。很多工具（如 git、pip）把有用信息打在 stderr。Agent 需要看到完整输出。
17-18区分超时异常：TimeoutExpired 单独 catch，给出明确超时信息，而不是笼统的「出错」。
10shell=True — 当前版本无安全限制。v0.4.0 企业级阶段会增加命令白名单和审批机制。

5. knowledge/search.py — 统一多源搜索

创建：v0.1.0 Day 8 · v0.2.0 修改行数：802 函数依赖：chromadb + bge 模型
在整个框架中的位置：数据层核心。不依赖 tools/ 或 core/，是独立的搜索引擎。v0.1.0 搜二源（年报+Agent工程），v0.2.0 升级为三源（+Wiki 262块）。
1"""统一多源搜索 — 一个查询并行搜索所有知识库。"""
2import os
3from pathlib import Path
4
5# 离线模式，避免 sentence-transformers 直连 huggingface
6os.environ["HF_HUB_OFFLINE"] = "1"
7
8import chromadb
9from sentence_transformers import SentenceTransformer
10
11# === 初始化 ===
12
14CHROMA_PATH = str(Path(__file__).parent.parent.parent / "AI工程/rag-project/backend/chroma_data")
15
16_client = chromadb.PersistentClient(path=CHROMA_PATH)
17
19KNOWN_COLLECTIONS = ["annual_reports", "agent_engineering", "wiki_knowledge"]
20
22_embed_model = SentenceTransformer(
23 "BAAI/bge-small-zh-v1.5",
24 local_files_only=True
25)
26
30def unified_search(query, top_k=5):
40 query_vec = _embed_model.encode(query).tolist()
41 all_results = []
42
43 for coll_name in KNOWN_COLLECTIONS:
44 try:
45 collection = _client.get_collection(coll_name)
46 results = collection.query(
47 query_embeddings=[query_vec],
48 n_results=top_k
49 )
50 for doc, dist in zip(results["documents"][0], results["distances"][0]):
51 all_results.append({
52 "source": coll_name,
53 "content": doc,
54 "distance": round(dist, 4)
55 })
58 except Exception:
59 continue # 集合不存在就跳过
60
62 all_results.sort(key=lambda x: x["distance"])
63 return all_results

逐行注解

6os.environ["HF_HUB_OFFLINE"] = "1" — 必须在 import sentence_transformers 之前设置。新版 sentence-transformers 不再尊重 HF_ENDPOINT 环境变量。这行防止每次启动时直连 huggingface.co 做 HEAD 验证（国内网络必超时）。
14Path(__file__).parent.parent.parent — 三层 parent：search.py → knowledge/ → ns-agent/ → AI工程/rag-project/backend/chroma_data。这个路径是跨项目引用：ns-agent 的 ChromaDB 数据存储在 rag-project 之下，共享同一份向量库。
16PersistentClient（不是 Ephemeral）——数据落盘，重启不丢。路径指向 rag-project 的 chroma_data 目录。
19KNOWN_COLLECTIONS — v0.2.0 关键改动。从 ["annual_reports", "agent_engineering"] 升级为三源。加新知识库只需在这里加一行，unified_search 自动覆盖。
40_embed_model.encode(query).tolist() — 把中文查询文本变成一个 384 维浮点数向量。bge-small-zh-v1.5 是 BAAI 的中文嵌入模型，专门优化中文语义。
43-59并行搜索循环——遍历三个集合，每个发一次 query 请求。结果按 collection 分组返回。用 try/except 包裹每个集合：某个集合不存在就跳过（continue），不阻塞其他集合的搜索。如果三个都没命中，返回空列表。
62sort(key=lambda x: x["distance"]) — cosine 距离越小越相关。三源结果混合排序后，Agent 看到的是按相关度排列的混合结果，不区分来源。

7. core/retry.py — API 重试

创建：v0.2.0 Day 9行数：361 函数依赖：openai
在整个框架中的位置：v0.2.0 新增。agent.py 的 API 调用不直接调 openai，而是包在 call_with_retry 里。指数退避 1s→2s→4s，最多 3 次。只重试可恢复错误（网络/限流/5xx），400/401 直接抛。

关键注解

10-11MAX_RETRIES = 3, BASE_DELAY = 1 — 常量而非硬编码。改配置只需改这一处。
14RETRYABLE = (APIConnectionError, APITimeoutError, RateLimitError, InternalServerError) — 白名单设计。不在元组里的异常（如 400 BadRequest）直接穿透，不浪费重试。
29delay = BASE_DELAY * (2 ** (attempt - 1)) — 指数退避：第1次等 1s，第2次等 2s，第3次等 4s。
23-25调用成功时直接 return fn(*args, **kwargs)，不经过任何后处理。retry 是透明包装器——成功路径零开销。

10. core/agent.py — Agent Loop

创建：v0.1.0 Day 8 · v0.2.0 修改行数：1332 函数依赖：registry + session + retry + errors
在整个框架中的位置：消费者。Agent Loop 不关心工具有哪些——它只从 registry 读、只调 registry 执行。它是整个框架唯一的「循环」——while True → LLM → 工具 → LLM → 输出。v0.2.0 新增了 session_id 参数（每条消息落库）、call_with_retry（API 调用包装）、NsAgentError（异常分类）。

v0.2.0 关键改动注解

10from core.retry import call_with_retry — v0.2.0 新增。替代裸 client.chat.completions.create。
11from core.errors import NsAgentError — v0.2.0 新增。chat() 的 except 子句用它区分错误类型。

45-54Agent Loop 核心——while True 永不退出（除非 break）。每次循环：① 发 messages 给 LLM ② LLM 返回 tool_calls 或文本 ③ 有 tool_calls？执行工具 + 结果塞回 messages + 继续循环 ④ 无 tool_calls？输出文本 + break。整个 while 循环里 messages 越滚越大——这是 Agent 的「记忆」机制。
