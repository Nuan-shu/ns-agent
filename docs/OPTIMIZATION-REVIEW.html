必修

4 项
#1

chat() 版本号错乱

P0
core/agent.py:95, 102

REPL 启动横幅打印 v0.1.0，但 pyproject.toml 已是 0.3.0，README.md 写 v0.3.0。用户首次启动会困惑「这到底是不是最新版本」。

问题代码
# core/agent.py
print("NsAgent v0.1.0 — 恢复了上次会话...")
print("NsAgent v0.1.0 — 输入 /exit 退出\n")
修复建议

把版本号做成常量（core/__init__.py 定义 __version__），所有打印都引用它：

# core/__init__.py
__version__ = "0.3.0"

# core/agent.py
from core import __version__
print(f"NsAgent v{__version__} — ...")
#2

TOOL_DEFINITION 命名违反 §3.1

P0
tools/time_tool.py:13

CONVENTIONS.md §3.1 明文写「常量名 = 功能名大写_DEF」。同目录其他工具都是 READ_DEF / WRITE_DEF / TERMINAL_DEF / PRICE_DEF / REPORT_DEF，唯独 time_tool.py 用了 TOOL_DEFINITION。

修复后
# tools/time_tool.py
TIME_DEF = {
    "type": "function",
    "function": {
        "name": "get_current_time",
        ...
    },
}
register("get_current_time", TIME_DEF, get_current_time)
#3

terminal_tool 硬编码绝对路径

P0
tools/terminal_tool.py:17
  • CONVENTIONS.md §8 明文要求「用 Path(__file__).parent 相对计算，不写死绝对路径」。
  • 换机器 / 改项目位置后 terminal 工具全错；当前能跑只是巧合。
  • 安全风险：别人 fork 你的项目，这个 cwd 会指向一个不存在的目录。
问题代码
result = subprocess.run(
    command,
    shell=True,
    capture_output=True,
    text=True,
    timeout=timeout,
    cwd="/Users/ns/Projects/ns-agent",   # 硬编码
)
修复建议
# tools/terminal_tool.py
from pathlib import Path

_DEFAULT_CWD = str(Path(__file__).parent.parent)

def run_command(command, timeout=30):
    try:
        result = subprocess.run(
            command, shell=True, capture_output=True,
            text=True, timeout=timeout, cwd=_DEFAULT_CWD,
        )
        ...

或者干脆删掉 cwd 参数（让 subprocess 继承父进程工作目录）。

#4

core/context.py 静默截断摘要

P0
core/context.py:50

middle_text[:2000] 没有任何提示就把中间对话砍到 2000 字符。LLM 看到的是「无征兆的信息丢失」，可能基于残缺内容产生幻觉。

问题代码
summary = f"[上下文摘要] 以下为之前对话的关键信息：\n{middle_text[:2000]}"
修复建议（最小改动）
SUMMARY_MAX_CHARS = 2000

truncated = middle_text[:SUMMARY_MAX_CHARS]
if len(middle_text) > SUMMARY_MAX_CHARS:
    truncated += "\n...（已截断）"
summary = f"[上下文摘要] 以下为之前对话的关键信息：\n{truncated}"

更彻底的方案：改用 LLM 自己生成摘要（既然已经累计 4000+ tokens，再调一次 API 做摘要更可靠）。

P1

强烈建议

5 项
#5

库代码用 print() 而非 logging（项目级）

P1
core/agent.py (14) · core/retry.py (1) · knowledge/ingest_wiki.py (5) — 共 20 处
  • REPL 用户和开发者看到同一份输出，无法分级（--verbose / --debug）。
  • 库代码（core / tools）的输出和 REPL 的提示符耦合，未来做 Web 界面 / IDE 插件时这层 print 全要改。
  • 工具出错时返回字符串给 LLM，但用户看不到 stderr。
修复建议
# core/agent.py
import logging
log = logging.getLogger("nsagent")

log.info("已加载 %d 个工具", len(tools))
log.debug(">>> 发送请求（%d 条消息）...", ...)
log.error("NsAgent 错误 [%s]: %s", e.code, e.message)

# main.py 入口
logging.basicConfig(
    level=os.getenv("NSAGENT_LOG", "INFO"),
    format="%(message)s",   # 保留原输出风格
)
#6

core/errors.py 异常体系未使用（死代码）

P1
core/errors.py:22-31
  • CONVENTIONS.md §3.4 说工具层「返回错误字符串不抛异常」，所以 APIError / ToolError / ConfigError 没人 raise 也没人 except。
  • core/agent.py:130 写的 except NsAgentError as e: 接不住 OpenAI 原生异常（重试耗尽后 retry.py:38 抛的是 APIConnectionError）。
修复建议（方案 A：retry.py 改抛 APIError）
# core/retry.py
from core.errors import APIError

if last_error:
    raise APIError(
        f"API 调用失败（已重试 {MAX_RETRIES} 次）: {last_error}",
        code="API_RETRY_EXHAUSTED",
        details={"original": str(last_error)},
    ) from last_error

或者方案 B：删掉三个子类，保留 NsAgentError，避免误导。

#7

match_skills 关键词匹配逻辑偏弱

P1
skills/registry.py:34-38

纯子串匹配 → 「毛利率」会被「成本率」误命中；「年报」会命中「年报纸」。技能是知识模块，误激活比漏激活危害大（System Prompt 膨胀，token 浪费 + 噪声增加）。

修复建议
import re

def match_skills(user_input: str) -> list[dict[str, Any]]:
    matched = []
    for _name, skill in _skills.items():
        keywords = [kw.strip() for kw in skill["trigger"].split("|")]
        for kw in keywords:
            # 单词边界匹配 + 不区分大小写
            if re.search(rf"\b{re.escape(kw)}\b", user_input, re.IGNORECASE):
                matched.append(skill)
                break
    return matched
#8

prompt.py 工具描述与 XXX_DEF.description 重复维护两套

P1
core/prompt.py:6-13

每个工具的 XXX_DEF["function"]["description"] 在 core/prompt.py 也写了一遍。**加新工具要改两处**，漏改一处 LLM 就看到不一致信息。

修复建议（单源真相）
# core/prompt.py
from tools.registry import get_tool_definitions

def build_prompt(skills_text: str = "") -> str:
    tool_lines = "\n".join(
        f"- {d['function']['name']}: {d['function']['description']}"
        for d in get_tool_definitions()
    )
    tools_layer = f"你有以下工具可以使用：\n{tool_lines}"
    layers = [IDENTITY, tools_layer, RULES, SAFETY]
    if skills_text:
        layers.append(skills_text)
    return "\n\n".join(layers)
#9

core/agent.py 顶层副作用太多

P1
core/agent.py:19, 21
  • load_dotenv(...) 和 client = OpenAI(...) 都是模块级副作用 — import core.agent 时就会执行。
  • CONVENTIONS.md §8 提了「私有连接：模块级 _client _embed_model 懒初始化」，但 agent.py 自己反而全局初始化。
  • DEEPSEEK_API_KEY 没值时 api_key=None 会等到第一次请求才报错。
修复建议
# core/agent.py
_client: OpenAI | None = None

def _get_client() -> OpenAI:
    """懒初始化 OpenAI 客户端。"""
    global _client
    if _client is None:
        load_dotenv(Path(__file__).parent.parent / ".env")
        api_key = os.getenv("DEEPSEEK_API_KEY")
        if not api_key:
            raise ConfigError(
                "缺少 DEEPSEEK_API_KEY 环境变量",
                code="CONFIG_MISSING_API_KEY",
            )
        _client = OpenAI(api_key=api_key, base_url="https://api.deepseek.com")
    return _client

锦上添花

9 项
#10

compress() 触发条件抖动

P2
core/agent.py:36 + core/context.py:43

进入压缩后每次循环都压缩，可能从 4001 立刻压到 ~2000 字符反复抖动（触发阈值与目标阈值都是 4000）。

修复：触发阈值 > 目标阈值，给一个滞回带（4500 → 3000）。

#11

memory/session.py 每次操作都开关连接

P2
memory/session.py — 21 处 _connect/close

SQLite 适合长连接 + 事务复用，每条消息 4 次系统调用浪费。建议用 threading.Lock + 单例连接 + check_same_thread=False。

#12

tools/registry.py 文件尾大段 docstring 误用

P2
tools/registry.py:26-37

模块 docstring 后又开了一个 """，实际成为模块 docstring 的延续（PEP 257 不推荐）。建议挪到 register() 函数 docstring 里。

#13

main.py 导入顺序违反 §1.2

P2
main.py:4-11

第 1 行是 from core.agent import chat（项目内），后面才是 import skills.finance。§1.2 要求「先 import 第三方再 from ...」。

#14

测试目录缺失

P2
项目根目录

pyproject.toml:60 配了 testpaths = ["tests"]，但项目根没有 tests/ 目录，pytest 直接报 "no tests ran"。建议至少加 3 个核心测试：test_registry.py / test_compress.py / test_skill_match.py。

#15

read_file 错误信息冒号不一致

P2
tools/file_tools.py + tools/finance/*.py

file_tools.py 用全角冒号（错误：），market_data.py / financial_report.py 用半角冒号（查询失败:）。建议统一为全角冒号（更符合中文排版）。

core/agent.py 导入分组空行不足

core/agent.py:3-7

§7 说「顶层函数之间 2 个空行」，导入分组之间也是 1 个空行。ruff 不会报但人眼读起来密集。

from pathlib import Path 写在 import re 前面，但字母序应该是 import re 在前（i < p）。
